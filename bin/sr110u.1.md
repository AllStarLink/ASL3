% SR110U(1) ASL3

# NAME

sr110u - program explicitly identified SR110U 110U-V223 radio modules

# SYNOPSIS

**sr110u** [**--port** DEVICE] [**--speed** BAUD] **version**

**sr110u** [**--port** DEVICE] [**--speed** BAUD] **radio** **--frequency** RX [OPTIONS]

**sr110u** [**--port** DEVICE] [**--speed** BAUD] **volume** **--level** LEVEL

**sr110u** [**--port** DEVICE] [**--speed** BAUD] **advanced** **--mic** LEVEL **--timeout** MINUTES **--vox** LEVEL **--power-saving** enable|disable

# DESCRIPTION

A distinct SR110U entry point sharing the packaged serial implementation with
`sa818`. Its protocol is fixed to `sr110u-v223`: an SA818 override is rejected
before opening a port. All writes require the exact `110U-V223` firmware reply.
`version` queries identity only; it does not certify compatibility or program.

This is not an SA818 module and is not a generic SR110U-family programmer.
Unknown/newer firmware is refused. The existing `sa818` interface and explicit
`sa818 --protocol sr110u-v223` preview compatibility remain available; use
`sr110u` for new SR110U integrations. It loads the sibling installed `sa818`
implementation, so both executables must come from the same ASL3 package.

# OPTIONS

The shared `sa818(1)` manual describes connection and channel options. For V223:

- `--frequency` is RX MHz; TX is RX plus `--offset` MHz.
- `--bw 0|1`: narrow/wide; `--squelch 0..8`; `--ctcss TX,RX` accepts independent tones or `None`.
- `--sr110u-flags 0..7`: bit0 busy lock, bit1 companding, bit2 low power. Default1: busy lock on, companding off, high power.
- Volume uses levels1..8. The older family manual lists1..9; level9 is not added to the tested interface.
- Advanced writes require mic1..8, timeout0..9 minutes (0 off), VOX0..8 (0 off), and power-saving enable/disable. Scrambling is fixed off.

DCS, tail and SA818 filters are not supported for V223. VOX is disabled before
advanced writes, and enabled last only when explicitly requested with power
saving disabled. Enabling VOX can transmit; normal AllStar operation uses PTT.

# PROTOCOL SOURCES AND LIMITS

The existing [SRFRS programmer and README](https://github.com/sp2ong/SRFRS/tree/10ac4d00b4802d394baf5a242b09f48fa3618bc7)
show `110U-V223`. The same repository includes the Sunrise SR-FRS V106 manual
and `SR110U.pdf` (V303). These are public mirrors of family documents, not a
claimed exact V223 vendor specification.

V106 section2.2.2 (PDF page16) specifies TX then RX and group flags. Sections
2.2.3–2.2.5 (pages17–18) cover power saving, version and volume; sections2.2.6–2.2.7
(pages18–19) cover VOX and `DMOSETMIC=mic,scramble,timeout`. By contrast V303
section2.2.1 (page14) specifies RX then TX; section2.2.5 (page16) has a two-field
MIC command and section2.3.5 (page23) includes timeout in `DMOFUN`. These layouts
are deliberately not substituted for V223.

Previous controlled testing obtained V223 command acknowledgments. ACKs are not
full settings readback, proof of RF mapping/power/audio/VOX/timeout behavior,
or persistence across a power cycle. A failure stops subsequent commands but
cannot undo earlier accepted writes.

# EXIT STATUS

0 for accepted operations (including identity-only queries); 1 for connection,
firmware-gate or command failures; 2 for invalid command-line options.
